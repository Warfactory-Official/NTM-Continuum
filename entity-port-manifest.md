# ntm-next entity port — manifest (2026-09-16; renderers added the same day)

Scope: every entity class ntm-next (`ntm-next/common/src/main/java/com/hbm/entity/**`) carries that new-hbm
did not already own, **copied** from ntm-next and then edited onto this port's architecture (Golem Core
facades, `DeferredRegister`, `ModDamageSources`, `HbmEffectNT`, `GolemNetwork`, `CompatSavedData`, `ChunkLoadingManager`).
`original-hbm` (1.7.10) is the behavioural spec; where ntm-next and 1.7 disagree the ntm-next code carries its
own `// 1.7:` notes and those were kept. Existing new-hbm entities were **not** replaced (missiles, bombs,
bullets MK4, RBMK, tool catalogue, fallout, MK5/Torex, etc. — the `KEEP` rows in
`port-tools/gen_entity_registrations.manifest`).

## Adaptation rules (port-tools/adapt_ntm_entities.py and hand edits)

`Services`/`Reg`/`RegistryHandle` → `DeferredRegister`/`RegistryObject`; `ValueInput/Output` → `DataIn/DataOut`
(`loadData/saveData/defineData`); `hurtServer`/`interact` overrides → `onHurt`/`onInteract` on `CompatEntity` bases; foreign
`x.hurtServer(...)` → `Compat.hurt`; `level.damageSources().source(K)` → `ModDamageSources.source(level, K[, direct, causing])`;
gamerules → `Compat.*`; `Services.NETWORK.sendToAllAround(new XPayload…)` → `EntityEffects.muke/teslaArc/gasFlame`,
`PlasmaBlastPayload.send`, `spawnShock`; `NtmContracts.CONVEYOR_BELT/ENTERABLE.at` → `api/conveyor/ConveyorLookup.at`
(block → block entity → folded multiblock core); `ModItems.X`/`ModBlocks.X` → this port's registries
(`rewrite_registry_refs.py`); `ModEntities.X` → whichever new-hbm registry owns it (`rewrite_entity_type_refs.py`; aliases
`BULLET_BEAM→BEAM_MK4`, `HIMARS→HIMARS_ROCKET`, `STRAY_SAW→SAWBLADE`, `EMP_LOGIC→ENTITY_EMP`); config accessors → the static
`GeneralConfig/WorldConfig/BombConfig/MobConfig` constants; `getNavigation().moveTo(` → `Navigations.navigateTo(` (the HBM
Stonecutter `snapTo(`↔`moveTo(` rule is reversible, so a raw navigation `moveTo(` breaks every non-active 26.1 node);
`InterpolationHandler` → `EntityInterpolation`/`interpolation()`; 26.1-only APIs → the Core helpers listed above.

## Gaps (explicit)

* **Renderer wave gaps** (see the renderer section below): the NTM cart chassis (`RenderNeoCart`, `cart.obj`) is not drawn —
  carts use vanilla minecart geometry; `RenderGrenadeUniversal` draws the grenade item instead of ntm-next's assembled shell mesh
  (no `GrenadeItemRenderer` in this port); `RenderGenericGrenade` draws the item model rather than a hand-sampled icon quad;
  `RenderMovingPackage` draws the supply crate for 1.7's loot crate; the RAD beast's gas-mask pass and ntm-next's mini-stack
  copies on belt items are not drawn; a tram/trailer off its rails draws at its (uninitialised) bogie midpoint. Rail blocks still
  have no OBJ models/blockstates (their block items are the only `hbm:` items without a model). `ModEntityItems` draw the
  1.7 sprites (`ModItemModels.entityItems`, 1.7 `<base>.<constant>` names kept); the cart item's chassis pass is fixed to
  `cart.vanilla` since `CART_BASE` has no select vocabulary; `crate_supply` is a `crate_can` cube.
* **Advancement criteria**: `HbmCriteria.orbit/detonation/bossKilled/satelliteAction` deliver to `Listener`s; no advancement
  subsystem consumes them.
